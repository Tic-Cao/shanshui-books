# 删除的艺术

光标在那一行命令后面闪。`git rm -r report-center`，我打完了，没有按回车。

屏幕左边是文件树，四百一十八个文件。大部分是 Python 文件，缩进两个空格，用的是二〇一五年的写法。最上面一个是 `manage.py`，最后修改时间停在二〇一九年六月。

办公室很安静。小唐在斜对面敲键盘，敲得很快，停一下，再敲。空调出风口有风声。楼下有人在卸货，铁板磕在地上，一声，隔几秒又一声。

删一个用了十年的东西，不是从这一行命令开始的。

它从七月十号开始。


七月十号，星期四，老周把我叫到小会议室。

他把笔记本转过来，屏幕上是一张表：十二行，每行一个客户名，最后一列是“最近请求时间”。

“这个服务，你听过吗？”

“听过。”我说，“没碰过。”

“把它关了。你来得晚，没有包袱。”

服务叫 report-center，二〇一五年四月上线。那时候我们的产品还没有导出功能，客户要看周报，只能自己截图、粘贴、排版。老徐花了三个星期写了这个服务，从数据库里取数，生成 Excel，放在一个地址上，谁有链接谁就能下。

二〇一七年，小方加了定时发送。每周一早上七点，系统自动把十二家客户的报表生成好，发到他们的邮箱，也留一份在地址上。

二〇一九年，产品里有了自己的导出。功能更全，能选字段，能筛时间。但那时候已经有十几家客户习惯了老地址，有的是把链接收藏了，有的是让 IT 写进了内部的定时任务。市场那边说，先留着吧，不差这一台机器。

一留，就是六年。

“为什么现在关？”我问。

“服务器要下线。”老周说，“而且那个链接没有登录，谁拿到都能下。审计那边提了两次。”

他停了一下，又说：“你先把依赖查清楚。查不清楚就别动。”

他说完就走了，会议室的灯没关。我坐了一会儿，把仓库拉下来。第一次打开这个项目，满屏都是 `print`，后面没有括号。

二〇一五年，产品只有网页版，客户要打印，只能截图。老徐那个服务解决的就是打印：生成一个格式固定的表，横着能放下十二列，A3 纸一张。

查依赖花了三个星期。

第一周我查得很慢。先把服务在本机跑起来，装 Python 2.7 装了三遍，有一个库的源已经关了，最后从别的地方找到一份旧的安装包。跑起来之后，界面只有一个输入框，填客户编号，点“生成”。

老徐在代码里留了一个后门：编号填 all，十二个一起生成。这个用法没有写在任何文档里，是我读代码读出来的。

先是代码。仓库里搜 `report-center`，除了它自己，还有两个地方引用：一个是网关的转发配置，一个是运维的部署脚本。

然后是定时任务。三台机器，一共三条：每天凌晨两点十分清理临时文件，每周一早上七点生成报表，每月一号凌晨三点生成一张汇总表。第三条，连老周都不知道。

第二条在一台没人认领的虚拟机上。资产系统里登记的使用人是老徐，状态还是“在职”。我发消息问他，他隔了一天回：那台机器我走的时候就交了，你们自己看吧。

然后是数据库。这个服务连的是主库，不是只读库。它有两张自己的表，一张存每天的任务统计，八百四十万行；一张存报表模板。还有一张表是它跟产品共用的，只读。

然后是日志。我把 nginx 的访问记录拉出来，按地址分组，最近九十天，一共十二个固定的来源。有的来自公司网络，有的来自客户那边的固定 IP。

十二个，跟老周那张表对得上。那张表是他自己做的，Excel，列宽调过，客户名后面还标了行业和项目数。

客服小吕听说要关，问了一句：那几家还在用的，会不会又打电话？我说会。她说那我先准备一下话术。

我写了一封邮件，发给这十二家客户的对接人。标题改了三次，最后用的是“每周报表导出功能下线说明”。正文很短：什么时候关，关之前可以改用哪个功能，需要帮忙可以找谁。

十一家回了。

有的说早就改用新导出了，只是旧链接一直挂着；有的问能不能把历史文件打包给他们；有一家打了个电话过来，问关了以后，财务那边每周一收的那个表怎么办。我陪他们把新导出的定时发送配了一遍，花了四十分钟。

一家做建材的，对接人回得很短：收到，我们早不用了，麻烦把二〇二一年的文件发我一份。我打包了十二个 Excel，四十多兆，用邮件发不过去，传到网盘，链接有效期设了七天。

还有一家回了一封长邮件，列了三个问题，第二个是：新导出能不能保留小数点后两位。我试了一遍，能。

第十二家没有回。

台州的一家做模具的公司。我打了三次电话，第一次没人接，第二次转到前台，第三次接通了，对方说，之前对接的王工已经离职了，这事他不清楚。接电话的人姓陈，我说陈工，他说，叫小陈就行。

“你们每周一早上会收到一封邮件，附件是一个 Excel。”我说。

“邮件？我这边没有。”

“可能是财务或者行政在收。”

他让我等一下，话筒放在桌上，我听见椅子响，脚步声远了。过了大概两分钟，他回来。

“问了。是行政那边一台电脑，每周一早上自动打出来。”

“打出来？”

“对。设了一个定时任务，早上七点打开那个链接，打印。打出来放在打印机上。”

“那台电脑很老吧？”

“XP 的，IE 还留着，因为要连打印机。”

“有人看吗？”

他笑了一下：“说实话，没人拿。每个月清理的时候一起扔掉。”

我让他把那个定时任务关掉。他说好，又问我，链接是不是以后都不能用了。我说是。他说行，反正也没人看。

过了一个星期，小陈发来消息，问能不能把这三年打出来的表给他一份电子版。我打包发了过去，一共一百四十多个文件。他回了一个谢谢。

回完消息，我在本子上写：第十二家，打印机。写完看了半天，觉得这行字很荒唐，又很合理。一个系统跑了十年，最后的使用者是一台打印机。


九月二十六号，星期五。

早上六点五十，我到公司。办公室里只有保洁阿姨，拖把靠在墙上，地面是湿的。

七点整，我手动跑了一次。

我在服务器上看着日志一行一行往下走：取数、生成、写文件、发邮件。十二个文件，用了两分十八秒。最后一个文件的生成时间是七点零二分十一秒。

我把它下载下来，打开。

表头是灰底，列宽被人手调过，“项目名称”那一列特别宽。表头还有合并单元格，“项目名称”横跨两列。数字都是文本格式，左上角带着小绿三角。最后一列叫“备注”，整列都是空的。这个模板是小方二〇一七年做的，八年里没人改过。

这套表还有个老毛病：用的是一个老库，单个文件最多六万五千行。有一家客户的表超过过一次，后面的行被截掉了，没人发现，直到月底对账。

我往下翻，翻到第四十几行，看见一个熟悉的名字。是我们自己公司的项目，二〇一八年的，早就归档了。

我把它打印了一份，A3，横着。打印机在走廊尽头，纸出来的时候还是热的。

那张纸我折了两折，夹在笔记本里。后来搬工位，翻出来过一次，纸已经软了。

八点四十，老周来了。他端着保温杯从我旁边过，停下。

“关了？”

“还没。十一点。”

“备份留了吗？”

“留了。两个地方。”

“行。”

他走了两步，又回头：“那个打印机的事，写进说明里。”


十一点二十，我把光标移回那一行。

回车。

终端滚了几屏，停下来。四百一十八个文件，四万一千二百三十六行，全部标记为删除。`git status` 里一片红。

我没有马上提交，先看了一遍 diff。四万行不是一次能看完的，我拖着滚动条，看它飞快地往上跑。有几个文件我认得，是二〇一七年改过的；大部分没见过。

删之前，我打开了一个叫 `test_export.py` 的文件。里面十一个测试，四个是跳过的，注释写着“2018 年就不过了”。

最后一次提交是二〇一九年六月，改了一个编码问题，提交信息是“fix”。

有一个文件的第一行写着：

`# TODO 2016-03-11 先这样，以后改`

后面没有了。“以后”一直没来。

提交信息我写了三行：

下线 report-center

服务运行 2015-04 至 2025-09，客户已迁移至新版导出。
最后一次运行：2025-09-26 07:00。

推上去。CI 跑了四分钟，绿的。以前是十一分钟，因为这个仓库的测试也要跑一遍。

运维的部署脚本里，我删了四行。网关的转发配置没有删，注释掉，留一个月的观察期。

然后打包。整个目录压缩成一个文件，一百八十六兆，放到归档盘的 2025 目录下。旁边放一个 README，三段：这是什么，谁写过，为什么关。

压缩包传上去用了十四分钟，归档盘的写入速度一直不稳定。传完我校验了一遍，解压，数了文件数，四百一十八个。

归档的不只是代码。我把十二个客户的模板、最近三年的生成文件，还有那份六页的下线方案，一起放了进去。

写“谁写过”的时候，我查了提交记录。老徐，二〇一五年四月到二〇一八年一月；小方，二〇一六年三月到二〇二〇年九月；后面还有零星的几个人，包括我自己，二〇二一年改过一个取数的 SQL。

老徐和小方都不在公司了。

我在 README 最后写了一句：如无必要，不要恢复。

下线方案写了六页，五节：范围、依赖、迁移、回滚、时间表。老周只改了一处，把“预计无影响”划掉，写成“可能有未发现的依赖”。

数据库的表没有马上删。

按流程，要先提变更单，写回滚方案，等审批。回滚方案我写得很简单：从当天凌晨的备份恢复，预计四十分钟。

变更单要填影响范围。我写了“报表导出，十二家客户”。表格里还有一栏叫“数据敏感级别”，我填了“中”。安全那边打电话来问，为什么要删，能不能只归档。我说归档过了。他说行，备注里写清楚。审批走了一天。

九月二十六号下午四点，DBA 权限开了四个小时。我先数了一遍行数，八百四十万，跟备份里的一致。然后删表。

两条 `DROP TABLE`，执行了不到一秒。

一秒，删掉的是十年里每周一早上七点跑出来的统计。我盯着那行 `Query OK` 看了一会儿，把窗口关了。

七点五十，事情做完。我坐在那儿等到八点，看着权限被收回。

删完那天下午，我照常开会、回消息、改一个下周要上的小需求。没有什么特别的感觉。直到下班，关电脑的时候，我才想起来，从明天起，再也不会跑那个两分十八秒的任务了。


* * *

九月二十九号，星期一。

九点二十，数据组的小顾在群里发了一句：“周任务量那张图空了，是不是库出问题了？”

我正在看另一件事，看到这句，心里先空了一下。

那张图在 BI 工具里，连的是只读库。他打开给我看：一张折线图，前面几个月都正常，从九月二十七号开始，线断了。图上面还有一条虚线，是上个月的同期。虚线还在，实线没了。

我问他这张图的数据从哪来。

他发来一段 SQL。

`FROM report_daily`。

就是那张我删掉的表。

我打开 BI 的后台，找到那条查询。最后修改时间二〇二一年十一月，修改人是一个我已经对不上名字的账号。

我们查了这张图的来历。二〇二一年建的，做的人已经不在数据组了。它没有写在任何文档里，也没有进过任何仓库。BI 工具用的是 `bi_reader` 这个账号，只读权限，谁都能建查询。

我查依赖的时候，查了代码、定时任务、数据库连接、访问日志。我没查 BI。

小顾问我能不能恢复。

我说能，但要等。

备份是每天凌晨两点全量。九月二十六号凌晨的那份里，两张表都在。我申请了一台临时库，把备份恢复进去，再把九十天的数据补回生产库。

恢复的第一步不是恢复，是确认备份可用。我先在临时库上把两张表导出来，数了一遍行数，才敢动生产库。

八百四十万行不能全补，只补了最近九十天，两百一十万行。从十点四十跑到十三点四十，三个小时。

补数据的时候，我在旁边看着进度条，中间去楼下买了一个饭团。回来的时候，进度条走了一半。

图在十三点四十二分恢复。小顾在群里发了一个“好了”。

过了几分钟，他又发了一句：以后删表能不能先说一声。

我回：能。

那天下午，我在下线清单里加了一条：

所有直连数据库的账号，逐个确认最近九十天有没有查询过要删的表。BI、报表、脚本、Excel 插件，一个都不能漏。

加完，我把这条发给老周。他回了一个字：好。


十月的一个上午，我把浏览器的书签栏整理了一遍。

有一条是二〇一七年存的，地址是内网的一个 IP，后面跟着一长串参数。我点了一下，出来一个 404 页面，白底黑字，很干净。

我看了两秒，把标签关了。

书签没有删。

那个地址现在指向一台空的服务器，过两个月，服务器也要退掉。

我想起二〇一七年第一次拿到这个链接，是在老徐的工位上。他用鼠标点了一下，说，就这个，收藏好。

report-center 的仓库还在，只是里面空了，剩一个 README 和一张截图。截图是二〇一六年做的，首页上有一个蓝色的按钮，写着“生成报表”。

十月的第一周，我在仓库列表里数了一遍，项目从四十三个变成四十二个。

小唐问我，那个服务真关了？我说关了。他说，我入职的时候它还活着。

他说完就走了，回工位继续改一个按钮的间距。


十月十号，中午，老周叫我下楼吃饭。

他走在前面两级台阶，手背在身后。走到二楼拐角，他停下来。

“归档盘那个目录，别叫 final。”

“叫什么？”

“2015-2025。”

“好。”

他继续往下走，走了两级，又停下来。

“那个 README，最后一句删了。”

“哪一句？”

“‘如无必要，不要恢复。’”

“为什么？”

“看着像遗嘱。”

他继续往下走。楼道里的声控灯亮了一下，又灭。
