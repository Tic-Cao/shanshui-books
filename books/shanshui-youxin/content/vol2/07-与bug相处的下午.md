# 与 bug 相处的下午

三点差十分，何姐在微信上发来一张截图。

截图是项目的时间轴，横轴上排着一串日期。她用红笔圈了三个点，旁边写：全部早了一天。

后面跟了一句：你们系统是不是把二月算错了。

我第一反应是不可能。日期这种东西，计算机算了几十年，轮不到我们算错。我回她：稍等，我看一下。

她说：不急，就是工人按这个排班，差一天要命。

我把截图放大。项目从二月二十六号开始，一共十天，结束日期显示三月五号。按日历算，二月二十六号加十天，应该是三月六号。确实少了一天。

我又看了一遍，觉得可能是她数错了。二月有二十九号，二十六、二十七、二十八、二十九、一号、二号、三号、四号、五号、六号。十天，从二十六号起算，最后一天是六号。

我给她回：何姐，你这边是按自然日还是工作日算的。

她说：自然日，合同上写的十天。

那就是六号。

我打开系统，新建了一个测试项目，开始日期填二月二十六号，工期十天。保存。时间轴的末端停在三月五号。

我又建了一个，开始日期填三月一号，工期五天。末端停在三月五号。这次是对的。

再试一个，开始日期填三月二号，工期三天。末端停在三月四号。二号、三号、四号，三天，对的。

问题出在跨过二月二十九号的区间。我试了二月二十七号，工期十天，末端三月六号，也少一天。二月二十八号，工期十天，末端三月七号，少一天。三月一号以后，正常。

我把这组数字写在纸上，看了半分钟。所有跨过二月二十九号的区间，都少一天。二月二十九号本身，像一个被漏掉的格子。

我给小唐发消息：你来看一下这个。

他端着杯子过来，站在我后面看了一会儿，说，缓存？

我说，不是，新建的项目也这样。

他说，那就不是数据的问题，是算的问题。

他把杯子放在桌角，拉了把椅子坐下。我们两个人盯着屏幕，像在等一个不会自己出现的东西。

我们先查了数据库。项目表里存的结束日期是三月六号，是对的。导出的 Excel 里是三月五号。说明问题不在存储，在计算。导出走的是后端那套逻辑。

我又看了前端。前端的时间轴是另一套代码，自己算一遍，不调后端。我把前端的源文件打开，搜“28”，也搜到了那个数组。两边都错，错得一模一样。所以页面显示和导出文件对得上，客户不容易发现，我们也不容易发现。

小唐说，这不是抄的吧。

我说，可能是同一个人写的，也可能是后来的人照着抄的。

他说，抄错的地方也一起抄了。

我说，代码里最常见的就是这个。一个人写错，十个人跟着错，错到最后，大家都觉得它是对的。

先看代码。

时间轴的计算在一个叫 timeline 的模块里，前端算一遍，后端算一遍，两边都有。前端负责显示，后端负责导出和提醒。我先看后端。

后端是一个函数，输入开始日期和工期，输出结束日期。函数不长，三十几行。前面是参数校验，中间是一个循环，按天加，最后返回。

循环里有一行：monthDays = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]。

我盯着那个 28 看了一会儿。

二月是二十八天。这个数组是对的，一年三百六十五天，平年。可是二〇二四年是闰年，二月有二十九天。

函数用这个数组判断每个月的最后一天。到了二月，它认为二十八号是最后一天，二十九号就被跳过去了。后面的日期全部往前挪一格。

就这么简单。

我又看了一遍。二〇一九年写的，那时候这个模块只有一个客户在用，功能也简单，只算工作日，不算自然日。后来加自然日，加导出，加提醒，都在这段代码上长出来。那个 28 像一块地基，上面盖了五层楼。

写这段代码的人，二〇二〇年离职了。他的头像在通讯录里还是灰的。我点开过一次，签名写着“好好生活”。我没有给他发消息。就算发了，他大概也不记得了。

我把这段代码给小唐看。他看完，说，谁写的。

我说，不知道，看提交记录。

git blame 显示，这段代码是二〇一九年四月写的，作者是一个已经离职的同事。提交信息只有四个字：时间轴。

代码上面有一行注释：简化处理，不考虑闰年。

小唐念了一遍，笑了一声，不是觉得好笑，是那种不知道该说什么的笑。

“不考虑闰年。”他说，“四年一次，也不算多。”

我说，四年一次，一次影响所有客户。

我把影响范围查了一遍。所有使用自然日工期、并且区间跨过二月二十九号的项目，结束日期都早一天。工作日计算的逻辑用的是另一套，没这个问题。导出 Excel 用的是自然日，也有问题。提醒任务在结束日期的前一天发，也早一天。

我们系统里有多少这样的项目，我不知道。二〇二四年二月二十九号以前开始、并且跨过二月二十九号的项目，都可能带着这个错误。有的客户可能没注意，有的注意到了，以为是自己数错。

我让运维拉了一份名单，受影响的客户一共十一家。有的是在建项目，有的是已经归档的。我把名单发给老周，他看完，说，先改代码，再一家一家打电话。

我说，要不要发个公告。

他说，先别发。先弄清楚每一家影响了什么。有的只是显示错一天，有的可能已经按错的日期签了合同。公告一出去，所有人都会来问，我们答不上来。

我说，好。

那天下午，我们打了六个电话。有一个客户的项目已经完工，尾款按错的日期结的，差一天，财务要重新走流程。还有一个客户说，难怪他总觉得时间轴对不上，以为自己记错了。没有人发火。大家都很忙，忙着过日子，没空为一个日期发火。

何姐是第一个来问的。

我给她打了个电话。

她接起来，背景里有叉车的声音，还是那样，滴滴滴。她走到一个安静的地方，说，查到了？

我说，查到了，是我们的问题。闰年，二月二十九号没算进去。

她沉默了两秒，说，我就说嘛，我数了三遍。

我说，对不起。所有受影响的日期，我们会重新算一遍，导出的表也会更新。你们已经排下去的班，可能要麻烦重新对一下。

她说，班倒是好说，就是有两个材料商，按这个日期订的货。早一天晚一天，仓库要压货。

我说，损失我们这边……

她打断我，说，先别说这个，你先把日期改对。别的以后再说。

我说，好。

挂了电话，我坐在椅子上，手心有一点汗。

这个 bug 不复杂。复杂的是它藏了五年，穿过无数次测试、上线、客户验收，一直没有被发现。因为它只在闰年出现，而我们的测试数据，大多是用二〇二三年的日期造的。

我想起自己刚工作那年，写过一个月份加一的 bug。日期是十二月三十一号，加一天，变成了同年的一月一号，年份没有进位。那个 bug 是我自己发现的，在上线前的最后一遍自测里。发现的时候，我坐在工位上，后背出了一层汗。

从那以后，我每次写日期，都会把十二月三十一号、一月一号、二月二十八号、闰年二月二十九号各试一遍。这个习惯保持了几年，后来慢慢松了。人就是这样，没出事的时候，总觉得下一次也不会出事。

小唐说，要不要先热修。

我说，先写测试。

他看了我一眼，没说话。

我知道他想说什么。客户在等，热修一个小时就能上。写测试要一个下午。可是如果不写测试，明年、后年、下一个闰年，同样的地方还会再错一次。

我打开测试文件，先写了一个用例：开始日期二〇二四年二月二十六号，工期十天，期望结束日期三月六号。运行，失败。红色的字，和我想的一样。

又写了几个：二月二十八号加三天，二月二十九号加一天，三月一号加五天，二〇二三年二月二十六号加十天。最后一个是通过的，平年没有问题。

然后改代码。

把那个数组去掉，换成日期库的方法。每个月有多少天，让库去算。闰年、世纪年、时区，这些事不该由我们记住。

改完，跑测试。刚才失败的几个，一个个变绿。二〇二三年的那个也还是绿的。

我又把测试数据换成了二〇二四年二月二十九号当天。新建项目，工期一天，结束日期应该是二月二十九号。通过了。

再加一个：二月二十九号加一天，应该是三月一号。也通过了。

小唐在旁边看着，说，你这是在拆炸弹。

我说，差不多。日期这东西，平时不出声，一出错就是一串。

我又加了一个二〇〇〇年的用例。二〇〇〇年是闰年，但一九〇〇年不是。日期库处理得对，我们的旧代码两百年都不会对。

小唐在旁边看着，说，二〇〇〇年都出来了。

我说，万一呢。

他说，你这属于过度设计。

我说，不是设计，是备忘。

改完代码，发版。灰度，观察，全量。时间轴上的日期一个一个往回长，像退潮以后露出来的礁石。

六点半，何姐发来一张新的截图。三个红圈都没有了，末端写着三月六号。

她说：对了。

后面跟了一个大拇指。

我回：给你们添麻烦了。

她说：做事嘛。

就没有再说。

我关掉聊天窗口，靠在椅子上。窗外的天已经暗了，园区的路灯亮起来，橘黄色的，一盏一盏。小唐还没有走，他在看自己的代码，屏幕的光照在脸上。

他忽然说，林哥，你怎么知道是闰年。

我说，不知道，试出来的。

他说，那要是试不出来呢。

我说，那就再试。

他笑了一下，说，你这话跟没说一样。

我说，本来就是。bug 不会告诉你它在哪儿，你只能一个格子一个格子地试。试到它出来，它就没那么可怕了。

他想了想，说，像找东西。

我说，像找东西。你知道它在这个屋子里，但不知道在哪个抽屉。只能一个一个拉开。

他点点头，转回去继续看屏幕。

我站起来，去茶水间倒水。茶水间的窗户开着一条缝，风进来，有一点凉。楼下有人在抽烟，烟头的红点一明一暗。

茶水间里有一袋别人放的饼干，我拿了一块，吃不下去，又放回去。胃里有一点空，是下午那杯咖啡的缘故。

我端着水回来，路过老周的工位。他还没走，在看一份文档。他抬头看了我一眼，说，那个日期的事，完了？

我说，完了。

他说，原因。

我说，闰年，二月二十九号没算。

他“嗯”了一声，说，这种错最麻烦。不是逻辑错，是常识错。逻辑错，你还能顺着推；常识错，你根本想不到那儿去。

我说，是。

他说，测试补了吗。

我说，补了。

他说，好。他又低头看文档，看了一会儿，说，回去路上买点吃的，别又煮面。

我说，好。

我回到工位，把桌面收拾了一下。键盘推回原位，杯子拿去洗，纸上的那组日期折了一下，放进抽屉。折的时候我看了一眼，二月二十六、二十七、二十八、二十九，四个日期排在一起，像四级很矮的台阶。

我关掉显示器。屏幕黑下去的一瞬间，能看见自己的影子。

走出办公楼，风比下午大。园区门口的银杏树落了一半叶子，地上铺着一层黄，踩上去没有声音。有人在路边等车，手机的光照着脸。

园区门口有一家便利店，我进去买了一瓶水。收银员在刷手机，头也没抬。我把水放在台上，她扫了一下，说，三块。

我走了两站路，才上地铁。

地铁上人不多，我找了个位子坐下。手机里有小唐发来的消息：林哥，我把那个闰年的用例加到回归测试里了。

我回：好。

他又发：以后每年二月都跑一遍？

我回：每年都跑。闰年跑，平年也跑。

他回了一个“收到”。

我把手机放进口袋，靠着椅背。车窗外的隧道壁一段一段地过去，灯光在玻璃上拉成一条线。

我打开手机日历，翻到二月。二十九号那一格是灰色的，比别的格子多出来一天。平时它不显眼，只有在闰年才出现一次。我想，这一天在系统里藏了五年，没有人看见。它不吵，不闹，只是让所有的日期往前挪一格。像一个安静的错字，印在书的每一页上，读到的人以为是自己看错了。

我想起何姐说的“差一天要命”。她说的时候语气很平，像在说一件已经发生的事。可那一天不是一个数字，是材料商的货车，是仓库的门，是工人的班。我们写错一个 28，下面接着的是很多人的安排。

这个念头让我坐直了一点。

那行注释我后来删了。删之前看了一会儿。“简化处理，不考虑闰年。”写这句话的人，当时大概觉得这是一个可以接受的取舍。四年一次，影响不大，先上线。很多错误都是这样开始的，不是恶意，是一个当时看起来合理的决定。

我把注释改成：闰年由日期库处理，不要自己算月份天数。写完，觉得还不够，又加了一句：测试里必须有二月二十九号。

小唐看见，说，你写这么长。

我说，给以后的人看。

他说，以后的人不一定看。

我说，那就给搜到的人看。

回到家，我煮了面。等水开的时候，我把手机放在桌上，看见何姐那条“做事嘛”，还没有回。我想了想，没有再回。有些话回多了，反而轻。

面煮好，我端到桌前。厨房的窗上有一层水汽，外面的灯看不清，只剩几团模糊的黄。我用手背擦了一下玻璃，擦出一道，很快又蒙上了。

桌角那张纸上还留着白天的字，铅笔写的，二〇二四，二月，二十九。我没有扔，夹进了一本书里。

第二天上班，我做的第一件事，是把所有跟日期有关的函数列了一张表。一共十七个。我一个个看过去，看到第三个，又发现一个只在月底最后一天出现的问题。

我把它记下来，排在待办里。

bug 是抓不完的。你只能跟它相处，一次一次地，把它的脾气摸清楚一点。
